# 桌遊系統 PRD (Product Requirements Document)

## 1. 專案概述

*   **背景與動機**：隨著數位化時代發展，傳統實體桌遊受到空間與時間限制。本專案旨在打造一個數位化的「桌遊系統」，讓大眾能夠隨時隨地與親朋好友一起回味同樂的時光，打破地理限制。同時透過系統輔助，降低複雜規則的學習門檻。
*   **目標用戶**：大眾（包含學生、上班族、家庭聚會成員等喜歡休閒娛樂與社交互動的玩家）。
*   **核心價值主張**：提供一個「可以讓大家憶起玩的遊戲」平台，結合動態計分與智慧化仲裁，讓玩家能專注於享受沉浸式的遊戲體驗，無需煩惱繁瑣的規則與人工計算。

## 2. 功能需求

以下列出系統的主要功能與對應的使用者故事：

1.  **動態計分**
    *   作為 **玩家**，我希望 **系統能即時更新並顯示所有玩家的分數**，以便 **我隨時掌握遊戲戰況而不需要手動計算與紀錄**。
2.  **沉浸式的遊戲**
    *   作為 **玩家**，我希望 **遊戲擁有直覺且具互動性的視覺設計與音效回饋**，以便 **我能更投入在遊戲情境與氣氛中**。
3.  **智慧化的仲裁**
    *   作為 **玩家**，我希望 **系統能自動判定玩家行為是否符合規則，並自動結算勝負**，以便 **減少玩家間的爭議，並讓遊戲流程更順暢**。
4.  **多人連線與房間系統**
    *   作為 **玩家**，我希望 **能夠建立專屬房間並產生邀請碼，或是透過邀請碼加入朋友的房間**，以便 **能與認識的親朋好友在同一個私人空間同樂**。
5.  **遊戲紀錄與成就系統**
    *   作為 **玩家**，我希望 **能查看過去的遊玩歷史紀錄以及達成的特殊成就**，以便 **追蹤自己的遊戲歷程並獲得成就感與話題**。

## 3. 非功能需求

*   **技術限制**：後端採用 Python Flask 框架，前端使用 Jinja2 模板渲染，資料庫使用 SQLite。
*   **效能考量**：系統需能支援單一房間內多人（如 4-8 人）即時遊玩，遊戲狀態更新的延遲時間應盡可能低（< 1秒），以確保流暢的體驗。
*   **安全考量**：確保使用者密碼加密儲存，並防範常見的網頁漏洞（如 SQL Injection, XSS），防止惡意玩家竄改遊戲分數或他人狀態。

## 4. MVP 範圍 (Minimum Viable Product)

*   **Must Have (必須有)**：
    *   基本的帳號註冊與登入功能。
    *   大廳建立房間、加入房間功能。
    *   至少一款核心遊戲的完整流程（包含智慧化仲裁與回合機制）。
    *   動態計分顯示。
*   **Should Have (應該有)**：
    *   房間內的即時聊天功能，增加互動性。
    *   沉浸式的 UI 介面優化（動畫過場、音效提示）。
*   **Nice to Have (可以有)**：
    *   成就徽章與全域排行榜。
    *   觀戰模式。
    *   擴充更多款不同的桌遊。
